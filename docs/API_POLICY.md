# API Policy (版本与弃用策略)

版本基线:1.1.0 生效。本文档是 Helix Support 对外 HTTP API 的兼容性承诺与变更流程,适用于所有 `/api/*` 端点(健康检查与 `/auth/*` 除外)。

## 1. 兼容性承诺

1. **响应体只增不改**:已发布响应中的字段不删除、不改类型、不改语义。新字段以追加方式加入,客户端必须容忍未知字段。
2. **请求参数只增不改**:已有请求字段不删除、不改类型、不改变默认语义;新增字段必须可选。
3. **端点不删不改语义**:已有端点的路径、HTTP 方法、成功状态码不改变。新端点以新路径追加。
4. **错误体**:自 1.1.0 起所有错误为 RFC 9457 Problem Details(`type/title/status/detail/instance` + `request_id` + `code`),详见 `docs/ERRORS.md`。顶层 `detail` 字段保留至 1.2.0 以兼容旧客户端。

## 2. 破坏性变更与弃用流程

任何违反第 1 节的变更视为**破坏性变更**,必须走弃用流程,不允许直接删除:

1. **标记弃用**:变更的次版本中,端点或字段同时发送 `Deprecation` 响应头(值为弃用起始日期)与 `Sunset` 响应头(值为移除日期)。
2. **至少一个次版本过渡**:从标记弃用到实际移除,至少跨越一个次版本(例如 1.1 标记 → 最早 1.2 移除)。
3. **changelog 记录**:每次 API 变化(新增/弃用/移除)写入 `CHANGELOG.md` 对应版本条目。
4. **快照门禁**:`api/openapi.json` 是 OpenAPI 契约快照;破坏性变更会导致 `scripts/openapi_snapshot.py` 门禁失败,需显式重新生成快照并提交后才可通过 CI。

### 弃用响应头示例

```
Deprecation: Tue, 14 Aug 2026 00:00:00 GMT
Sunset: Thu, 14 Aug 2027 00:00:00 GMT
```

## 3. 分页与游标

- 列表端点使用不透明游标(`X-Next-Cursor` 响应头 + `cursor` 请求参数);客户端不得解析游标内容。
- 游标只在相同过滤条件内有效;修改过滤参数后必须丢弃旧游标。
- `offset` 分页为兼容保留,新客户端应使用游标。

## 4. 幂等

- 消息发送(`POST /api/conversations/{id}/messages`)支持 `Idempotency-Key` 请求头(8–128 位 `[A-Za-z0-9._:-]`)。
- 同一 key 重放返回首次结果,不产生副作用;key 相同但载荷不同返回 409 `idempotency_conflict`。
- 客户端应在重试时复用同一 key。

## 5. 认证与租户

- 所有 `/api/*` 请求必须携带 `X-API-Key`;多租户部署还需 `X-Tenant-Id`(与 key 绑定的租户一致,否则 403)。
- 权限通过角色映射(`admin`/`supervisor`/`operator`/`channel`/`viewer`),详见 `docs/ERRORS.md` 的权限标注与 OpenAPI 每个操作的描述。

## 6. 版本号

- API 版本遵循语义化版本(SemVer)。路径中不嵌入主版本号;兼容性由本文档与快照门禁保证。
- `GET /api/me` 返回 `role` 与权限列表,客户端应基于权限而非角色字符串做功能判断。

## 7. 变更审批

- 新增端点/字段:常规 PR,快照需重新生成。
- 弃用:PR 说明 + changelog 条目 + 响应头。
- 破坏性变更(未走弃用):禁止;唯一例外是安全修复,且需在 changelog 中显著标注。
